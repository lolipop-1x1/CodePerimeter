本文依据 [需求讨论](map.md) 的 Q1–Q6 答复整理，等待整体确认。第一阶段交付观察与及时发现；完整产品的外传控制目标仍见 [产品上下文](../../CONTEXT.md)。

## 目标与最小使用流程

在 macOS 本机用 CLI 配置一个或多个保护目录并管理后台监控，完成必要授权后继续正常使用应用。用户能通过终端回查谁在访问哪些文件，发生集中访问或疑似打包时得到告警与系统通知，并能回查对应证据。

后续技术讨论已明确第一版包含系统启动即运行的后台监控，不依赖终端或用户登录；后台授权和事件传输仍须验证。CLI 用于配置、管理与回查，详见 [技术讨论](technical-design.md)。

## 已确认范围

- 观察选定目录内所有进程的文件活动，显示进程身份；身份无法取得时标注未知。
- 记录带读权限的文件打开、可读内存映射等真实事件，明确事件类型、路径、时间与来源，不称为实际读取字节量。
- 汇总同一进程在观察窗口内访问的不同文件数；同一文件重复访问另计活动频次，不重复增加不同文件数。
- 发现与选定目录有关的外部归档命令和落盘归档迹象。命令执行只称为打包命令迹象，文件活动关联不证明归档内容。
- 同进程读取文件后在内存中压缩列入必测；验收其访问记录和批量提醒，不要求确认压缩运算本身。
- 普通文件活动进入 SQLite，CLI 支持在终端查看；批量访问与疑似打包汇总告警并发送 macOS 系统通知。
- 从触发事件发生或批量门槛达到时起，初版目标为 3 秒内生成告警；有 macOS 桌面会话时同时验收 3 秒内发出系统通知。无桌面会话时照常记录，进入桌面后汇总补发，后台运行不受此影响。

## 最小规则与实现候选

- 批量访问采用“同一进程在滚动 10 秒内访问至少 50 个不同文件”作为已确认的可调整原型初值，仍须样本校准；达到门槛即触发，不等待窗口结束。
- 外部归档命令与相关归档生成迹象不依赖批量文件数门槛；必须保留它们与选定目录的关联依据，不将任意系统归档命令算入项目。
- 对已观察到访问选定目录的进程，关联其可见的归档输出线索，覆盖目录内输出与临时目录输出；系统无法提供关联时记录缺口。
- 普通搜索、索引和构建也可能满足批量规则，提示描述“批量文件访问”，不判定其已经压缩或泄露。同一轮活动合并提醒，保留后续证据。
- 已确认优先验证 `eslogger`；本机已核查支持事件列表，真实输出与后台接入仍需验证。它需要 root 与完全磁盘访问，不作为正式产品的稳定接口。
- 本地保存最小事件与告警证据，不保存文件正文、完整命令行、环境变量或凭据；只保留识别相关工具和路径需要的字段。
- 已确认使用 Rust CLI 核心、仅采集器 root、分析程序普通用户运行、SQLite 结构化保存；这些选择尚未实现。
- 用户新增从 Agent 历史会话提取项目目录候选并一次批量加入监控的入口，先通过 CLI 完成；只提取目录与来源元信息，不分析会话正文或持久化原始历史。
- 已确认 CLI 支持手动多个目录，以及候选预览后按需批量导入；监控目录集合持久化，新会话不自动扩大范围。
- 首批历史来源为 Codex 与 Claude Code CLI 本机记录，分别适配元信息格式；手动目录不依赖历史格式。格式版本与实际覆盖须验收。
- SQLite 保存失败但采集与分析仍可运行时，继续实时提醒并明确显示保存缺口；采集停止另报故障。
- 同一进程运行实例、同一规则 60 秒内合并告警，首次即时通知，后续及时追加数量和证据；不同进程或规则分别提醒。3 秒通知目标针对首次新告警，合并追加不重复发送。
- Codex 提取会话头部与每轮记录中的明确目录；Claude Code 提取受支持记录中的实际 cwd，不反解存档文件夹名。失效／未知目录显示状态，不能静默算作没有项目。
- 采集未启动、权限不足、已知丢事件或通知失败时明确显示缺口，不能显示完整监控或把未知统计为零。

## 最小验收

验收使用合成项目与固定操作脚本，保存版本、系统与授权状态、预期路径、真实事件、告警及通知发送时间。组件测试通过不代替本机事件验收。

| 场景 | 必须取得的结果 |
| --- | --- |
| 单文件读取与可读映射 | 实际支持的事件能定位来源进程与路径，准确标注类型；不要求每次实际读取都对应新事件 |
| 批量读取 | 满足配置门槛时产生汇总告警，同文件重复打开不会冒充多个不同文件 |
| 外部 tar／zip | 记录相关命令与项目关联、可见归档生成线索，覆盖项目内与临时目录输出 |
| 同进程落盘归档 | 无独立 tar／zip 进程时，记录项目访问与可见输出迹象，不能凭后缀证明内容 |
| 同进程内存压缩 | 监控启动后读取足够多合成文件再内存压缩；访问记录与批量告警成立，提示不声称确认压缩 |
| 已在应用内存中的数据 | 压缩时没有新打开／映射事件的情况明确作为覆盖限制，不报告“没有发生压缩” |
| 正常搜索、索引与构建 | 操作继续完成，记录提醒频次与延迟，作为阈值校准对照，不显示泄露判定 |
| 及时提醒与运行状态 | 每次新告警生成目标不超过 3 秒；有桌面会话时通知发送同样不超过 3 秒，合并追加不重发；实际到屏展示另验，权限或采集失败可见 |
| 系统后台与桌面会话 | 系统启动即采集，关闭终端／注销不中断；进入桌面后补发未展示告警汇总；后台授权、恢复与受控停止可核验 |
| 历史目录与手动配置 | Codex 初始／每轮目录、Claude Code 实际元字段、手动多个目录、去重／失效／版本缺口与重复导入可核验；新会话不自动扩展已选集合 |
| SQLite 与故障 | 项目／进程／时间／文件查询关联证据；保存失败显示缺口，实时分析可用时继续提醒；不报告完整记录 |

实际采集完整性、CPU／内存、丢事件与通知展示需要报告，不提前宣称达标。阈值以下或监控前已加载的内存压缩不承诺产生批量告警。

## 本阶段不交付
