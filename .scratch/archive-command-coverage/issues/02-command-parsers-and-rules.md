## Answer

- 系统 exec 适配器按 tar、zip、ditto、单文件压缩与 7-Zip／RAR 家族提供全部 14 个名称的真实解析入口，无逐工具配置。支持直接输入、多个输入、适用的递归／压缩级别／保留源文件与输出选项；反向模式先于路径解析排除。
- tar 的目录切换、老式选项与选项值消费，zip 的密码／输出参数，xz 的线程／后缀参数，zstd 的显式输出与 stdout 先后顺序，以及 7-Zip／RAR 的粘连密码和 stdin 标签分别处理。BSD tar／bsdtar 的 -I 为列表别名，gtar 的 -I 消费外部压缩器；gtar 的 -H 消费格式，BSD 的 -H 为无值修饰符。BSD 的 --mac-metadata、--no-mac-metadata、--cd 与 --block-size 不借用于 gtar；双方已核对的 --blocking-factor 仍支持。7-Zip 创建到 stdout 限于已核对的 tar、gzip、bzip2 与 xz 格式；RAR 不伪造通用 stdout 创建模式。
- zip（含 --out）、7z／7zz 与 RAR 的无扩展名目标按已核对工具语义补后缀。7z／7zz 的已核对格式为 7z、zip、tar、gzip、bzip2 与 xz，未知格式报告缺口；已有扩展名保留原名。7z／7zz 与 RAR 使用 -si 时清空被工具忽略的磁盘选择器，仅保留明确输出并报告输入来源未知，避免用磁盘选择器伪造项目证据。RAR 7.23 不支持的 -afzip／-afrar 报告参数缺口。
- ArchiveCommand 保留旧单输出字段，并增加默认空的多输出字段。默认多文件压缩准确保留多个输出；未展开的递归目录不凭目录名杜撰压缩输出。规则关联明确输入、明确项目输出或已有同进程访问证据，cwd 本身不证明 stdin／隐式输入来源。
- 列表／间接输入、未知选项／模式、缺少参数值与无法解析相对路径产生固定覆盖缺口；纯 stdin／隐式输入报告来源未知。列表、argv、环境、正文和密码值不进入标准事件或错误。
