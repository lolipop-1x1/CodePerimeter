# 中英文与可扩展多语言支持

日期：2026-10-07
状态：Q1—Q10 已确认；实现与隔离验收已完成，真实后台双语通知到屏及 Mac 重启复验待验证。

## 目标

项目支持中文与英文，并方便后续扩展更多语言。语言切换覆盖完整用户使用流程，不只替换导航标签。

## 已确认

Q1：采用完整用户使用流程覆盖。

Q2：首批为简体中文与英文；繁体中文及其他语言通过相同机制后续扩展。

Q3：以当前 Mac 用户为单位保存统一产品语言偏好；网页切换影响后续通知、产品生成的原生交互文案和默认 CLI 人类提示，关闭网页及重启后保留。CLI 可临时指定语言，不改变保存的偏好。

Q4：日期和数字按选定语言格式化，保留本机时区与 24 小时制；导出机器字段、时间戳、事件标识及错误码保持稳定。

Q5：默认跟随 macOS 首选语言，中文匹配简体中文、英文匹配英文，未支持语言回退英文；侧栏底部提供跟随系统／简体中文／English 菜单，手动切换立即生效并保存。

Q6：已有事件／状态代码用于提供当前语言解释，历史原始文本仍可查看；未知旧提示、第三方文本与用户备注保留原文并标注。已送达通知保留原语言，后续通知使用当前偏好。

Q7：首批双语文档覆盖 README、CLI 使用说明和后台安装／权限说明；研究、架构、ADR 与历史验收文档保留现有中文，按需要后续扩展。

Q8：按最新回复取消语言贡献功能及相关指南，不提供用户导入语言包。保留集中管理语言资源的机制，便于项目后续增加语言。

Q9：默认 README 使用英文，提供简体中文版本；两个版本顶部互相链接。

- 网页七个页面、详情、弹窗、空状态、输入校验、错误说明和辅助功能标签。
- 系统通知的行为标题、正文与操作名称。
- CLI 帮助及面向人的提示；产品生成的系统交互说明纳入范围。
- README 与用户使用说明；研发与历史验收文档保持现有中文。
- 事件字段、机器错误码、文件路径、程序身份及用户输入的备注保留原值。
- 翻译保持证据口径：文件打开／映射不表述为确认读完，批量访问不表述为确认内存压缩，归档迹象不表述为确认外传。

## 实施前工程事实

- 网页使用 React 与 Carbon，尚无国际化依赖；用户文案分散在页面、格式化与 API 错误映射中。
- 日期、时间与数字显示多处固定使用 `zh-CN`。
- 网页 HTTP 错误已有部分稳定错误码，可供按语言显示说明；内部控制错误与 CLI 底层错误也包含可读字符串，需要区分产品说明与原始错误。
- 系统通知标题、正文由 Rust 生成，通知操作按钮由 Swift helper 生成；目录选择提示由原生适配器提供，需一起本地化。
- macOS 自己生成的管理员／通知授权窗口遵循系统语言，不由产品语言偏好强行改变。
- 历史健康记录分开保存 component、code、state 与 detail，detail 包含既有中文原文；内部控制错误文本目前混合代码与可读说明。
- JSON 导出序列化既有记录，CSV 有固定机器列名；本轮多语言工作保持已有机器接口与数据原值。
- 当前只有浏览器主题等偏好，尚无产品语言偏好；通知在后台生成，不读取浏览器本地存储，统一偏好必须让后台可读取。
- 保留现有监控范围、规则语义和数据接口，避免把语言资源与业务判定耦合。

## 文档交付范围

- `README.md`：英文默认入口；`README.zh-CN.md`：简体中文版本。
- `docs/usage.md` 与 `docs/usage.en.md`：现有中文使用说明及英文版本。
- `docs/service.md` 与 `docs/service.en.md`：现有中文后台安装／权限说明及英文版本。
- 双语文档提供相互切换链接；不新增语言贡献指南。

## 实施与验收约束

- 产品文案采用稳定文案标识与完整句子模板；动态名称、计数和路径使用参数，避免在业务代码中逐处拼接中英文。
- 网页、通知、CLI 与原生交互共享产品语言偏好的含义；具体资源格式与持久化落点在实施前按现有权限边界评估。
- 支持命名参数、复数、日期／数字本地化与缺失翻译回退。首批两种语言的资源缺失、参数不一致应在 CI 中失败；运行时缺失提示回退英文，防止空白或直接显示内部文案标识。
- 翻译资源随程序交付；日常使用不依赖在线翻译或外部语言服务。
- 不重写历史证据、备注或机器导出；不因语言切换重启采集或改变监控范围。
- 验证七页及弹窗、详情、表格、空状态、错误和辅助功能标签；覆盖两种语言、双主题及既有窗口宽度，关注英文扩展后的溢出。
- 验证跨标签页、关闭网页后的新通知、重启保留、CLI 临时语言覆盖、未知系统语言回退，以及旧记录和机器导出的稳定性。
- 用合成语言资源验证增加资源和登记后可被识别、切换及回退，不要求逐处修改页面和规则业务代码；其他语言的文案质量、文字方向与排版另按其实际需求验收。

## 实施技术选择

网页采用 i18next／react-i18next；网页与原生／CLI使用分域扁平JSON资源，共用语言登记表。当前用户私有目录的 `language.json` 保存产品语言偏好，网页经过原有入口认证修改，后台和CLI按需读取；不改动证据SQLite模式或写入职责。Rust使用CLDR复数规则，Swift接收同次通知的语言与动作文案，旧请求保留中文兼容。新增资源键、参数及源码静态引用均进入CI检查。

参考：[React 翻译接口](https://react.i18next.com/latest/usetranslation-hook)、[语言回退](https://www.i18next.com/principles/fallback)、[复数](https://www.i18next.com/translation-function/plurals)。
