# 通知行为说明与告警详情跳转

日期：2026-10-07
状态：用户已确认通知显示程序名、项目名和必要的短文件名；要求明确区分大量文件访问与压缩行为。

## 范围

- 三类通知分别说明大量文件访问、启动压缩／打包命令、疑似压缩文件生成／修改。通知不把文件打开／映射写成已读完，不把归档命令或输出写成压缩成功或外传。
- 默认显示程序可执行文件名、项目目录名和可确认的输出文件名。完整路径、PID 与证据解释留在详情页；显示值去除控制字符并限制长度，未知值明确标注。
- 点击通知正文或“查看详情”打开对应告警详情；摘要打开告警中心。网页已运行则复用入口，未运行则启动入口。
- 通知只保存告警 ID，不保存网页令牌、端口或可执行路径。普通用户通知 App 从当前 UID 构造固定安装入口并验证受保护文件，再执行固定 CLI 参数。
- 支持通知 App 已退出后的冷启动点击；旧通知无 ID 时打开告警中心。记录过期／清除／尚未落库时显示明细不可用，并保留返回告警列表的入口。
- 点击只导航，不自动标为已读／已处理，不执行管理员操作。通知首次发送与点击结果分别验证。

## 验证

1. 合成三类通知解释正确；归档输出文件与源文件分别保存，兼容旧告警 JSON；匿名导出处理新增路径。
2. CLI／网页保留认证约束，详情入口校验 ID；刷新、关闭详情、返回列表及缺失告警给出明确结果。
3. 原生助手编译、有效／非法元数据、发送请求与点击路由检查；实际点击通知分别测试已启动和未启动控制台。
4. 真实通知到屏和冷启动点击需现场证据；组件或浏览器测试不能替代系统点击验收。

## 进展

- 三类行为文案、短名称、候选输出字段、原生点击响应及网页详情入口已实现。
- 192 项 Rust、15 项网页测试、3 项真实浏览器用例、严格 Clippy 与双架构编译通过；新增入口升级及匿名导出回归通过。
- 新版已安装并启用，真实通知点击通过：已运行控制台打开批量访问详情；退出控制台且通知助手已退出后，点击 ZIP 输出通知重新启动控制台并显示对应详情。用户确认打开地址，现场浏览器与认证接口核对告警和候选 ZIP 文件一致。
- 证据与覆盖边界见 `docs/validation/web-console-validation.md`。


## 现场补充

- 用户观察到两条同名 FDA 项。现场“在访达中显示”均指向同一个正式安装位置；同 UID 只有一个 collector、一个 daemon 和一个 notify。主二进制的当前签名为 ad-hoc，默认 designated requirement 含本版 cdhash，重复项很可能与历史更新授权残留有关，未直接读取或修改 TCC 数据。
- 无稳定签名时，权限跨版本识别存在限制；依据 [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。不在本轮通知功能修改中重置权限、删除授权项或引入新的签名信任。
- 安装／启用经系统授权成功，既有 FDA 由用户恢复，真实采集、数据库与原生通知角色已就绪；匿名批量访问、程序内 ZIP 与 tar 覆盖三类告警，六条关联告警均取得原生发送反馈。短时横幅无法可靠自动点击，两次真实点击由用户完成；冷启动后采集仍 connected、数据库 ready、通知角色在线，零丢帧／保存缺口，点击未改变已读或已处理状态。
