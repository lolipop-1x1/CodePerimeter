# 归档命令扩展验收

日期：2026-10-05。依据 [已确认规格](../../.scratch/archive-command-coverage/spec.md)。当前解析与组件回归已完成，全部 14 个工具的真实采集验收尚未完成；以下入口与场景不代表已经通过。

## 实现与边界

用户选定目录后，程序自动识别全部受支持名称，不增加逐工具配置。归档命令迹象使用明确输入／输出或已有同进程项目访问证据关联目录；工作目录本身不证明标准输入来自项目。

| 名称 | 常见支持调用 | 排除与限制 |
| --- | --- | --- |
| tar、bsdtar、gtar | 创建、追加、更新；`-f` 输出、`-C` 切换输入目录；`-f -` 标准输出 | 解包、列表；列表文件报告缺口。BSD `-I` 为列表，GNU `-I` 为压缩器 |
| zip | 创建／添加、更新、递归、压缩级别、`-P` 密码；归档输出为 `-` 时标准输出 | 查看、删除、纯完整性检查；密码不持久化 |
| ditto | 显式 `-c` 归档、适用的 `-k`／`-z`／`-j`、标准输出 | 复制、解包；BOM 列表报告缺口 |
| gzip、pigz | 默认压缩、保留源文件、递归、级别、自定义后缀、明确输入到 `-c` | 解压、测试、列表；多个输入保留多个适用输出 |
| bzip2、pbzip2 | 默认压缩、保留源文件、级别、明确输入到 `-c` | 解压、测试；pbzip2 未核对长别名或互斥模式组合保留缺口 |
| xz | 默认压缩、保留源文件、级别、线程、自定义后缀、明确输入到 `-c` | 解压、测试、列表；文件列表报告缺口 |
| zstd | 默认压缩、级别、线程、输出路径、明确输入到 `-c` | 解压、测试、列表、训练；文件列表报告缺口 |
| 7z、7zz | `a`／`u`、递归、级别、密码；`a -so -ttar` 等支持格式到标准输出 | 解包、列表、测试、删除；`@` 列表报告缺口。标准输出不承诺 7z 格式 |
| rar | `a`／`u`／`f`、递归、级别、密码 | 解包、列表、测试、删除；列表报告缺口；不承诺创建归档到标准输出 |

操作与选项按对应工具处理，不能把其他工具的同名选项解释为已支持。XZ、bzip2、zstd 的已核对操作模式按最后设置生效。输出模型兼容旧的单输出 JSON，并增加默认空数组的多输出字段，无需数据库 schema 迁移。

这些规则发现操作线索，不证明压缩成功、读完文件、外传或拦截。改名／未知工具、内部压缩库、已在内存中的内容和跨进程管道来源还原保留原有覆盖边界。

## 工具与真实入口

额外测试工具存放在项目外私有目录，不构成监控运行依赖，也不随开源代码分发。开放工具采用官方源码、官方 Homebrew bottle 或官方发布包；本机 Homebrew 安装因旧 Command Line Tools 失败，准备工具时未升级系统开发工具。RAR 使用用户已接受的官方限期试用包，仅用于本机合成验收。

构建后，在已具备采集所需完全磁盘访问的终端执行持久化入口：

```sh
cargo build --release --locked
sh scripts/run-archive-validation.sh
```

此验收入口要求 Python 3.11 或更新版本，以使用标准 `process_group` 启动参数；持久化入口在管理员授权前检查，直接运行 Python 入口也会用固定 `python_version_unsupported` 分类拒绝旧版本。这只是验收脚本要求，不改变产品或 Rust 的最低版本。

入口要求本机管理员授权，仅准备受保护的验收二进制并运行采集；不安装 launchd、不改变 FDA 或系统安全设置。已有服务、端点或活动进程按原有准备入口拒绝覆盖。缺少采集授权、工具或真实证据时保留失败结果，不使用 fixture 替代。

真实主链路为 eslogger → Rust 解析 → 目录规则 → SQLite → 通知发送反馈。每个名称执行正向、适用的更新／标准输出及反向／项目外对照。10 个支持纯标准输入的工具另在保护目录 cwd 内实际接收合成字节，不提供明确项目输入。负例另有合成操作身份与独立来源屏障证据，不能把空数据库当作成功；先确认主 exec 已处理本次精确 run、实际目标 PID／代次，stdin 再确认同身份的 `archive_input_source_unknown` 已保存，然后启动独立文件屏障，并要求无项目命令告警。分流后不跨来源比较序号；旧单路仍核对缺口来源序号早于屏障。其他场景的孤立缺口不能替代。通知发送延迟从实际触发事件计算，目标 3 秒内，不能将 `sent` 解释为通知已到屏。

准备阶段的错误与取消只输出固定分类，不回显异常或命令。真实与演练共用工具操作成功判定，版本探针缺失或失败不得判为演练成功。独立观察器意外 EOF／非零退出使真实验收失败，包括最后一个负例之后；主动正常停止不误报。重复停止保留首次清理结果，采集失败与清理失败分开记录。主链路缺口只增加可选的 PID、代次与来源序号，旧来源 JSON 可读，不增加原始事件保存或数据库 schema 迁移。

sudo 旁路保留授权终端的 SID／控制终端，并隔离 PGID，避免 eslogger 压制同进程组事件；启动时再次核验实际 root 进程的 PGID 与调用方不同。标准输入仍关闭，进程清理继续核验本次 launcher 血缘、root 身份与固定可执行路径，仅控制确认的精确 PID。旁路 stderr 只在有界内存中识别 sudo 授权缺失、ES 拒绝、来源启动错误或未知诊断，摘要仅保存静态分类、退出码与读取完整性，不保存原文。启动失败先等待诊断读取，sudo 授权缺失优先报告 `sidecar_sudo_authorization_required`；无法分辨时仍保留身份未确认。

旁路序号诊断只保存前 8 个缺口的前后 event／global 序号及数字总计，倒退继续判失败；缺失总计是跳号的算术数量，不能推导每个失败场景分别丢事件。周期子进程扫描间隔为 50ms，同时保留首尾扫描、快速退出检查与超时清理。摘要仅复制现有 pipeline timing 的固定整数白名单，正例另记录来源到接收、接收到 outbox、outbox 到发送反馈的延迟；缺少接收时间时保留未知。数字诊断不替代健康检查，3 秒门禁仍从实际来源触发事件起算。

延迟诊断入口只执行 ditto、bzip2、pbzip2、zstd 的创建与明确输入到标准输出共 8 个正例：

```sh
sh scripts/run-archive-validation.sh --diagnose-source-latency
```

该模式按目标 PID、进程代次和实际可执行名称，将主链路 exec 与仅订阅 exec 的独立旁路配对。旁路只在内存保留解析后的 UTC 纳秒来源时间、完整行接收时间和执行窗口；新增摘要字段只保存数字差值、布尔值及固定失败分类，不保存 PID、完整路径、命令行、原始时间字符串或事件。主来源时间为毫秒精度，比较时按相同精度核对；缺失配对、时间或时间不在执行窗口内使诊断不完整。结果单独使用 `source_latency_diagnostic_passed`／`source_latency_diagnostic_failed_or_partial`，仍要求主告警与通知发送符合原有 3 秒门槛。该入口与 `--exercise-only` 互斥，默认 92 项流程保持原有范围；8 项通过不代表全部 14 个名称完成验收，也不自动证明积压的原因。

本机 tar 入口是指向 bsdtar 的链接，验收允许已核实的 tar／bsdtar 实际身份，gtar 保持独立。7z／7zz 保留已有实际身份映射。汇总记录实际观察到的 executable 名称，两个调用标签不代表两个不同实现；进程代次、输入与输出证据仍须精确匹配。

原始系统事件只在内存处理。合成项目、独立数据库与必要证据位于项目外权限受限目录；公开材料只保留工具名称、版本、计数、延迟和固定失败分类。验收不会导入真实历史目录。

## 当前验证

- 最新分流版本真实 8 项：各场景均有精确主 exec／旁路来源配对、命令告警与 sent，生成最大 1230ms、发送最大 1593ms，均满足来源起算 3 秒目标；主链路共 11 告警／11 发送反馈。但是总体仍为 `source_latency_diagnostic_failed_or_partial`：activity 路 95073 条中有 13 条问题行、20 个 gap 报告，global／per-type 各 10 个，7 帧重合，不能解读为 20 个独立丢失事件。global 跳号的算术缺失数为 10，集中于采集启动后约 1.2 秒；exec 路 212 条无缺口。桥接／宿主丢弃和数据库缺口计数为 0，隐私标记未持久化，两侧 root 清理完成；这些指标不能排除 ES 客户端内核丢失或 eslogger 输出前过滤。
- 系统 man 明确说明 eslogger 会抑制同进程组事件；本机 macOS 15.6.1 二进制静态检查发现，处理新消息时，同组分支调用 mute 并绕过正常消息保留路径。因此它可能制造输出序号缺口，但当前汇总无法证明具体缺号由该分支产生。最小对照让每个自有 eslogger 独立 PGID，保留 SID／控制终端、固定可执行路径和精确 Child 回收；不忽略 gap、不改变 3 秒或整体健康门禁。真实效果仍待重跑。
- 新分组候选的生产 spawn 入口经过真实普通用户 PTY 红绿回归，两路 PGID 独立、SID／TTY 继承、精确 Child 与正常信号停止通过；完整 Rust 1.88／locked 回归 125 项通过（另 1 原 helper 忽略），fmt、严格 clippy、diff／敏感扫描与 release／locked 构建通过。当前构建 SHA256 为 `27337277a8a367c60862adf0963936d0556355d07fd51ff656f8aaf2fc283697`。独立审查 Standards 硬违反／heuristic 均 0；Spec 范围扩大／可证实现错误均 0，保留 1 项 P2 验证缺口（新版真实 8／92 项及 SIGKILL／launchd 回收未验），独立 PTY 窄回归 1 项通过。此构建未改变 Python 验收门禁。
- 修复候选将主来源拆为 exec 与其余八类 activity，各自有界队列、公平转发、独立序号核验与健康；fork／exit 留在 activity，与文件事件保序。模型、持久化与内存去重增加固定 stream，已知 PID／代次仍按共同运行关联，未知代次不跨路猜关联。旧单路 JSON 默认 combined，SQLite schema 保持 3。负例补主 exec 的有界内存处理回执与先确认后屏障门禁，两路都观测到一致来源版本且无已知缺口才能通过。详情见 [实现边界](../../.scratch/archive-command-coverage/source-partition.md)。最新子集只验证本次 8 场景的时效，整体健康与完整 92 项仍未通过。
