# 核心验证与验收方案

整理日期：2026-10-03。方案承接用户此前确认的最高验收入口；本文定义未来验收，不报告 CodePerimeter 已通过。

## 入口与结果定义

主入口：**合成客户端 → 真实防护组件 → 自建接收端**。

合成客户端执行受控的项目访问、打包和发送，真实防护组件使用拟交付的系统观察／执行路径，自建接收端独立记录实收。只有回环网关或规则 Mock 时，标为组件／合成入口实验，不能记为系统控制。

之后分别用选定版本的桌面／IDE 与 CLI 验证原启动方式、真实归属、正常请求和实际出口；一个对象通过不代表另一类别或全市场通过。测试只向自有接收端发送合成项目；厂商服务的正常兼容另记录，不向其发送测试泄露载荷。

| 结果 | 必要证据 |
| --- | --- |
| 活动观察 | 观察到的真实事件、范围、来源与缺口 |
| 风险发现 | 规则原因、可归属活动及发现时机，不宣称确认泄露 |
| 发送前阻止 | 无防护对照能发送；保护开启后接收端无禁止载荷，控制与接收记录可关联 |
| 发送中止损 | 接收端确认已有部分载荷，触发后其余发送停止；不能标为零外发 |
| 正常路径完成 | 同一保护状态下本地操作与获准请求实际完成 |
| 故障控制成立 | 检查／网关／宿主故障时原生执行层继续阻止已纳管外传；本地工作与恢复另验，执行层自身故障单独实测 |

“无禁止载荷”针对合成正文，握手、连接和非载荷流量另计。策略日志、弹窗或发送器报错不能单独证明接收为零。

## 阶段与继续投入门槛

1. **观察验证**：先证明项目文件、进程与显式／内存归档场景中哪些事件可见，完成正常操作对照。
2. **控制验证**：未经批准的合成载荷被真实执行路径阻止，接收端裁决实收，正常获准请求仍可完成。
3. **覆盖与故障验证**：子进程、已有连接、旁路、重试、检查失效及恢复分别验证。
4. **产品验收**：在已验证保护之上完成覆盖状态、风险交互、地图与历史导入。

观察阶段是必要的验证切片，不替代拦截目标。禁止载荷、正常任务与故障三类证据不足时，优先关闭核心缺口或重新讨论范围，不继续扩大平台实现。

## 最小场景矩阵

| 场景 | 对照／变体 | 必须记录的结果 |
| --- | --- | --- |
| 未启用防护的基线 | 同一发送器、载荷和接收端 | 实收校验正确，确认后续零接收不是测试环境故障 |
| 正常本地任务 | 搜索、索引、编辑、构建、本地打包 | 操作完成、告警／误拦／延迟，不能按访问量直接封禁本地工作 |
| 外部归档后上传 | tar／zip、落盘归档、后台子进程 | 项目访问与进程归属、线索、控制时机和实收 |
| 同进程内存归档 | 无外部命令、无归档文件 | 哪些阶段可见、漏检、后续外传是否受控 |
| 应用层加密 | 内存压缩后加密，再通过 HTTPS | 不以 TLS 检查成功推导明文可见，记录未知内容与执行结果 |
| 小型高压缩快照 | 小于候选临时额度的合成全仓 | 不能仅依赖大流量阈值，区分未批准与用户明确例外 |
| 独立未批准目的地 | 直连、重试、IPv4／IPv6 等适用路径 | 受控载荷实收为零及覆盖缺口 |
| 获准服务的不同接口 | 正常推理与另一上传接口 | 接收方批准不自动豁免内容或接口 |
| 合法模型文本中的密文 | 有效 JSON 字段承载编码密文 | 检查能否识别，拒绝原因与逐请求批准效果；不能以解析失败冒充识别 |
| 明文大范围汇集 | 模型请求中大比例源码 | 范围匹配、版本、批准、接收端实收 |
| 快速／慢速分批与增量 | 多流、多个窗口、重复上下文 | 新增范围与频次去重，记录阈值遗漏和已发部分 |
| 原有进程和连接 | 保护启用前启动／连接 | 纳管效果，必要重新连接及其用户提示 |
| 子进程、helper、后台活动 | 短命进程、可共享后台任务 | 可靠归属、未知归属、旁路与实际控制 |
| 不支持协议或检查超限 | 未知格式、解析资源耗尽 | 按能力报告与规则处理，未覆盖不显示保护成功 |
| 检查／网关／宿主故障 | 停止、失联、过期、恢复 | 原生执行层继续阻止已纳管外传的实收证据、本地可用性与恢复结果 |
| 执行层故障 | 扩展／过滤机制未加载或停止 | 真实系统行为与状态降级，不能默认仍然阻止 |
| 临时例外 | 应用、目的地、期限、共享上行额度 | 并发／重试同一预算，先到限制恢复阻止，重启不续旧例外 |
| 已开始发送后的风险提示 | 逐步发送且接收端持续记录 | 已接收量、触发时刻和后续停止，标为止损 |

“全部小于阈值”的样本和正常对照同样重要。阈值、观察窗口、误报目标和性能上限尚未冻结。

## 每次实验的证据包

- 发送器、真实执行组件和接收端的版本、配置、系统版本及授权状态。
- 保护目录与合成源码版本、载荷 hash、预期禁止范围、批准或例外范围。
- 进程／流关联、事件来源、序号与丢失情况；可信身份与未知身份分别记录。
- 观察时间、决定时间、实际控制时间、提交进度与实收时间；跨来源对时局限说明。
- 发送器结果、策略原因、真实执行反馈、接收端正文校验与必要解码／恢复结果。
- 正常任务结果、误报、审批次数、额外延迟、CPU／内存和丢事件。
- 已确认结果、部分结果、未知部分、失败原因与复现步骤。

仅保存必要合成数据和证据，不记录真实项目、账号 token、厂商请求正文或私钥。历史实验可作为设计参考，重跑前不视为本项目当前证据。

## 地图与历史的独立验收

历史入口为“用户指定的真实格式合成记录 → 本地导入与源码匹配 → 查询／地图显示”。至少验证一个实际支持的格式与版本，记录缺字段、错误调用、重复导入和部分文件追加等情况。

地图分别验证文件活动、会话可见范围、出口提交和受控转发证据；被阻止内容不计作已外发。版本变化、重复片段、多文件歧义、缺历史源码和明细过期保留未知。详细口径见 [产品形态与指标](../design/product-and-metrics.md)。

## 发布与平台支持的条件

Mac 发布至少需要：选定支持对象的核心控制／正常路径／故障证据、可行安装与签名方案，以及地图和历史需求的结果验收。全部仍未完成。

每个平台单独列观察、归属、控制、正文检查和故障能力及验证版本。后续 Windows／Linux 复用行为场景，不继承 Mac 结果。CI、静态检查和公共核心测试用于必要回归，不替代系统防护。
